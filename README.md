# 赛博斗蛐蛐 · Cyber Crickets

四个 Agent 在同一张网格地图上争夺领地和资源。玩家可以观看单局，也可以从侧边新建八名 Agent 的多轮比赛，逐轮推进赛程并查看排名与报告。胜负由整局的持续控制表现决定。

**[在线试玩](https://yunnre060214-sudo.github.io/cyber-crickets/)**

## 当前玩法

- 单局可选 60、90 或 120 秒，默认 90 秒；观战速度有 1×、2×、4×。
- 四方同时观察每次决策前的地图，各自提交一个相邻格动作，再统一结算成功率和同格冲突。核心区不可被翻色。
- 战场包含地形阻力、普通与高价值资源，以及按赛局进度触发的资源潮汐、中央节点和终局超频。
- 实时展示累计 VP、当前 VP/s、领地、资源、翻色次数、决策耗时、策略意图和落点；ACO 风格 Agent 的信息素可叠加显示。\n- 实时 VP 折线图使用固定坐标系：X 轴固定为 0 到比赛总时长，Y 轴固定为 0 到该时长的理论 VP 上限。历史线段不会随当前最高分重新缩放，只有曲线末端继续生长。\n- 单局结束后自动生成胜因分析、领先易手次数，以及 VP / 领地时间序列图，便于看出胜负是在哪个阶段形成的。\n- 支持直接导出 **Markdown 完整对局日志**：包含游戏规则与字段语义、对局配置、算法阵容、最终结果、重大事件、每秒局势快照和逐次算法决策，可直接交给没有前置上下文的 AI 复盘。
- 主界面只保留开始、暂停、赛事和比赛设置四个高频入口；时长、速度、种子、出生轮换、观战图层、重开、新地图与阵容统一收进“比赛设置”。

## 比赛赛程

侧边的“新建比赛 / 查看赛程”提供六种八人赛制：单循环七轮、双循环十四轮、八人淘汰赛、两组各四人的小组赛、三轮瑞士轮，以及小组前两名交叉晋级的混合赛。每次点击“进行下一轮”会在后台完成本轮对阵，赛程、积分和报告随之更新；刷新页面后，可以在当前浏览器继续比赛。

赛程使用**一对一换边双局**，与四方单局并存。每个对阵在同一地图种子下打两局，双方交换左右出生位置；按累计 VP 决定胜负。循环赛、小组赛和瑞士轮胜 3 分、平 1 分、负 0 分，同分依次比较 VP 净胜值、累计 VP 和种子位。淘汰赛的 VP 完全相同时，依次用翻色次数、终局领地和固定种子打破平局。小组赛只产生两个小组排名；混合赛才会产生总冠军。

“总览、赛程、排名、报告”子菜单会显示后续对阵、两局 VP、晋级路径与最终结果。赛程计算在 Web Worker 中运行，避免完整 90 秒对局的快速模拟阻塞页面；比赛记录保存在浏览器本地，暂不跨设备同步。

## 胜负规则

每秒获得的胜利点数为：

```text
VP/s = 10 × (0.65 × 领地格数 / 4096 + 0.35 × 已控制资源价值 / 地图资源总价值)
```

时间结束时，累计 VP 最高者获胜。资源价值为 1 或 3；新增资源后，分母同步更新。**普通扩张、翻敌方格和抢到资源的瞬间不另加 VP**，翻色次数只用于观战统计。攻击的收益来自随后对领地或资源的控制时间。

行动间隔对所有 Agent 相同。显示的决策耗时是本机测得的观测数据，**不决定行动次数，也不表示已实施统一 CPU 预算**。Monte Carlo 采样使用固定迭代次数，因此设备快慢不会改变其决策轮数。

## 种子与出生轮换

网址会记录 `seed`、`agents`、`duration` 和 `rotation`。例如：

```text
https://yunnre060214-sudo.github.io/cyber-crickets/?seed=20260927&rotation=1&agents=aco%2Cminimax%2Cqlearn%2Cvoronoi&duration=90
```

在同一代码版本下，用相同参数重开，会得到相同地图、决策和结果。四个轮换使用同一张地形与资源图，把每个阵营依次放到四个出生角；目前需要手动切换并分别跑四局，自动赛事汇总尚未加入。Q-Learning 每局从空 Q 表开始，按 `state → action → reward → nextState` 更新，避免浏览器此前保存的学习状态改变复现结果。

## Agent 阵容

内置 18 个可选策略，其中部分名称指向**算法风格或启发式**，并不宣称完整实现同名经典算法：

| 显示名称 | 当前决策方式 |
| --- | --- |
| BFS 风格洪流 | 依据邻格连贯性铺开，不执行层序遍历 |
| DFS 风格穿刺 | 沿上次方向深入，不维护深度搜索栈 |
| Greedy 疯狗 | 优先当前高价值格 |
| Random 赌徒 | 从候选边界随机选格 |
| ACO 风格蚁道 | 成功路径留下信息素，随时间蒸发 |
| Voronoi 圈地 | 比较本方和对方核心的距离 |
| 势场 流体 | 用资源吸引力和敌方压力选格 |
| PID 风格稳健 | 按面积目标误差调节攻守倾向 |
| Q-Learning 学习者 | 使用离散状态、四个宏观动作和时序差分更新 |
| 防反启发式 | 估计局部最坏敌压，不构造 Minimax 博弈树 |
| Monte Carlo 采样 | 固定次数评估候选动作，不进行 MCTS 树搜索 |
| 资源链启发式 | 靠近未控制资源，不生成 MST |\n| Frontier Runner | 低地形阻力优先，以阵型完整度换铺图速度 |\n| Raider 掠袭者 | 专攻敌方薄弱边界与孤立格 |\n| Turtle 堡垒 | 沿高邻接密度区域紧凑扩张 |\n| Resource Denial | 优先夺取敌占资源并封锁高价值节点 |\n| Momentum 变速器 | 原创自适应策略，按面积、敌压和比赛阶段动态变速 |\n| **最强** | 规则感知 VP 复合优化器：估算成功率与剩余赛程 VP 边际收益，并综合资源、领地、翻色、局部攻防、资源路径、地形、比赛阶段和失败记忆 |

所有策略通过 `selectAction(view) → action` 接口接入；Agent 只接收候选动作及其观测特征，世界变化由规则模块统一处理。\n\n### 「最强」策略\n\n“最强”是当前版本专门针对 Cyber Crickets 规则设计的复合效用优化器，目标函数尽量贴近真正决定胜负的**累计 VP**，而不是只追求当前一步得分。它会为每个合法候选动作估计占领或翻色成功概率，并结合剩余比赛时间计算潜在的长期领地 VP 与资源 VP；攻击敌方格时还会考虑夺取控制权带来的攻防 swing。\n\n它同时评估局部己方支援、敌方防守、资源距离与 `resourcePull`、地形阻力、敌压、阵型连续性、比赛阶段和终局超频，并记忆近期目标及连续失败目标，对反复失败的硬点动态降权。极小的 seeded jitter 只用于打破近似平分，因此同种子仍可复现。\n\n“最强”遵守与其他 Agent 相同的信息边界：**只读取 `view/options` 中公开给 Agent 的状态，不读取完整隐藏地图、未来随机数或其他策略无法获得的信息。** 因此这个名称表示“按当前规则设计的理论最强目标”，并非未经实验验证的绝对强度结论。统计强度应通过大量地图种子、四出生位轮换和足够多对局进行 Benchmark。

## 项目结构与运行

```text
index.html       页面结构
styles.css       视觉与响应式布局
app.js           控件、渲染和对局呈现
match.js         地图、同步决策和对局流程
rules.js         种子随机数、出生轮换、VP 和冲突结算
agents.js        内置策略
tournament.js    循环、淘汰、小组、瑞士轮的赛程与统计
tournament-ui.js 侧边抽屉、报告与浏览器保存
tournament-worker.js 赛程后台计算
test/            Node 内置测试，无第三方依赖
docs/            赛制规则与实现计划
.github/workflows/deploy-pages.yml
```

本地验证：`npm test`。本地预览：`python3 -m http.server 8080`，然后访问 `http://localhost:8080/`。项目是纯静态网页，提交到 `main` 后由 GitHub Actions 自动部署到 GitHub Pages。

## 后续方向

当前版本提供可复现的单局、赛后时间序列分析和可保存的多轮赛程。后续优先考虑可变参赛人数与更丰富的实时数据分析，再扩展对称 Benchmark 地图、真实搜索算法和可度量的计算预算。现阶段的四角轮换入口尚不等于严格公平的 Benchmark，当前地图和事件仍保留娱乐局的随机性。
