# 2.0 赛事解释补齐 · 2026-10-01

赛事此前只保存胜者、累计积分及逐局结果。此次把决胜依据随赛事保存，刷新后可以查看，也能在 Markdown、HTML 和完整赛事包中带走解释。

浏览器验收同时发现并修复了一个加载缺口：已结束赛事重新打开时，加载返回值没有携带已保存的逐局结果，详情的第二次渲染因此隐藏了回放按钮。加载现在同时返回实际逐局结果，刷新后仍可打开每局回放，无需重跑赛事。

## 行为与兼容

- schema 3 赛事快照新增 `fixtureReasons`，以 fixture ID 对应 `vp`、`captures`、`territory`、`seed` 或 `draw`。只有已结算对阵有理由；同分等待加赛会在详情明确显示。
- 理由从已有赛果推导，使用原有 VP 的 `1e-9` 判定容差，不重新选择胜者。现代与经典赛事的聚合函数、随机决胜、比赛引擎和策略均未修改。
- 旧快照不含此字段时仍能恢复，读取与导出会补齐理由。经典解释放在适配器快照外层，冻结的 `rawLegacy` 内容保持一致。
- 导入先验证原文件完整性、配置、赛程和实际逐局数据，再校验理由。矛盾、缺漏或未知对阵的理由会在写入前拒绝。
- 旧文件补齐解释后重新封装完整性摘要，导入 ID 继续按原文件计算；重复导入同一个旧文件不会新增赛事。
- 产品及比赛数据版本保持 2.0.0 / schema 3。这是原 2.0 赛事解释的补齐，不更改既有规则。

## 验证

本地基线 `npm test` 为 134/134。11 项理由测试先运行失败，复现理由缺失；另一个实际逐局回放加载测试在修复前失败。最终完整回归为 **146/146**，`npm run build` 和 `npm run verify:dist` 均通过。

测试覆盖五种已结算理由、容差内 VP 同分、等待加赛、旧快照恢复、经典原始快照不变、真实双局结果持久化、三种导出、旧文件完整性与重复导入、错误理由在写入前拒绝。

浏览器验收扩展已有实际淘汰赛流程：运行、暂停、刷新、继续、核对每个已结算对阵的理由，再次刷新，并实际下载 HTML、Markdown 和完整包，检查解释与持久化结果一致。GitHub CI 在桌面 Chromium / WebKit、Pixel 7 / iPhone 13 模拟视口执行这些动作；main 发布后同一流程再次访问实际 Pages 站点。

原 [148 局验收报告](../benchmarks/v2-acceptance.md)继续对应首发时冻结的源码摘要。本补丁没有重新运行该策略矩阵，不将历史报告的摘要写成补丁摘要；引擎、策略及冻结经典源码未变，相关回归与黄金值随完整测试重新验证。
