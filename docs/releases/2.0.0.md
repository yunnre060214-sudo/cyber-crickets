# Cyber Crickets 2.0.0

发布状态：2.0.0 已正常合并 main，并通过 Pages 公开站点验收。发布说明补全后的最终提交继续由同一发布流程核对。

## 本次升级

从单局演示扩展为无需账号、无需后端的浏览器算法竞技平台，提供竞技场、赛事中心、回放分析、策略实验室和算法图鉴五个工作区。原生 ES modules、Web Worker、Canvas/SVG 和 IndexedDB 组成运行时，开发依赖不进入发布产物。

- 21 种公开策略，包括 A* 四邻路径规划、边界调度器和 UCB1；三种规则模式、四种对称地图、单挑和四方阵容。
- v2 采用 20 ms 整数 tick、100 ms 同步决策和统一工作预算。随机流按用途派生，倍速与实际耗时不改变结果。
- 六种赛事形式、每图换边、逐局账本、检查点、保存恢复、去重与跨标签页写入冲突检查。
- 回放支持逐 tick 棋盘、比分和事件重建，并下载离线 HTML、Markdown、完整 JSON.gz。存储不可用或配额不足时仍可直接下载当前捕获的数据；旧记录可分页访问。
- 实验支持预览真实局数、暂停、取消未完成任务、保存继续、分种子统计、bootstrap 区间和本地单挑 Elo。
- 五个工作区适配手机；棋盘和曲线显示实际数据，高分时向上扩展。构建仅发布 dist，所有运行模块和 Worker 位于同一源码版本目录。

## Rulings I made

以下按实际决策顺序列出全部冲突裁定及判断错误的代价。

1. 网络克隆不可用时，以核对后的本地镜像和 GitHub base-tree API 维护分支；执行器随后离线时继续通过 GitHub 和实际 CI 验证。原因：保持完整文件树与正常父提交；代价：本地与远端 SHA 不同，必须额外比较树以避免漏文件。
2. 本地基线 subprocess 的 EPERM 按环境故障调查，保留原测试并要求 CI 实际执行。原因：不能把环境阻塞改写成产品通过；代价：需要等待可执行环境验证。
3. 旧入口源码形状及模拟 app 测试按替换后的实际模块更新，同时保留 URL/状态行为测试并增加真实浏览器检查。原因：用户行为是兼容标准；代价：旧标记形状不再是回归断言，必须依靠新入口完整性和浏览器行为。
4. 本地 Playwright 下载返回无效 ZIP、云浏览器不能访问本地预览、执行器离线及人工云浏览器会话无法连接时，以分支 CI 和真实 Pages 流程完成浏览器验证。原因：实际浏览器运行仍是发布门槛；代价：CI 环境与用户设备仍可能存在差异。
5. 队列协议加入内部 resultAck，只有结果持久化完成后才推进下一任务。原因：避免重复结算及刷新后丢腿；代价：新旧 Worker 混用不兼容，由同目录内容版本构建防止混用。
6. 将超过 30 条历史记录的访问问题从 Minor 改为 Important 并修复。原因：直接影响已有存档恢复；代价：增加分页维护。
7. 对审查未判断的浏览器及线上发布，要求实际 CI、线上 SHA/摘要及真实操作证据。原因：源码审查不能证明发布成功；代价：浏览器环境差异仍需明确。
8. 对跨设备和 1800 秒内存性能，仅披露实际 400 秒矩阵，不承诺所有设备的 1800 秒性能。原因：不把时长输入支持等同于性能实测；代价：低内存设备长局仍可能需要优化。
9. 保留并明确分种子的单局胜率平均；本地单挑 Elo 使用换边双局累计 VP 胜负。原因：两种统计回答不同的问题，现有口径明确后成立；代价：该胜率与累计 VP 对阵胜率可以不同。
10. 策略强度只报告冻结样本及全部败局。原因：固定地图、阵容和种子无法证明通用最强或样本外提升；代价：其他配置中排序可能变化。

11. 对发布复核中的回放测试刷新竞态，以页面可见终态和真实滑块时长同步，而不改写正确的保存数据。原因：IDB 已保存并不等于异步列表和详情已更新，仍需实际打开完整记录并完成跳转/下载；代价：检查验证最终可用状态，不保证加载中的每一帧都没有短暂旧内容。
