# 比赛赛程设计

目标：在现有四方单局之外提供可保存、可分轮推进的八名 Agent 赛事。赛事以一对一为赛程单位；每个对阵用同一地图种子打两局并交换出生侧，以双方累计 VP 判胜。单局观战页保持四方模式。

## 赛制与规则

- 单循环：八名参赛者采用圆圈配对法，七轮、每轮四个对阵；每两人恰好相遇一次。双循环共十四轮，每组对手在另一轮使用新种子再赛一次。
- 淘汰赛：四场八强赛、两场半决赛，以及决赛和季军赛；每个对阵的胜者晋级。
- 小组赛：按种子序号蛇形分为两组，每组四人单循环，三轮结束后给出两个小组排名，不虚构跨组总冠军。
- 瑞士轮：八人三轮，第一轮高低种子配对，后续按积分接近优先、避免重复交手配对；三轮后按积分榜排名。
- 小组加淘汰：先完成三轮小组赛，两个小组的前两名交叉进入半决赛，随后进行决赛和季军赛。

胜负：双局累计 VP 高者赢，平分记平局；淘汰阶段平分时依次比较双局翻色总数和终局领地总数，再用赛事种子决定极少数完全相同的情况。积分榜胜 3、平 1、负 0；排序依次比较积分、VP 净胜值、累计 VP 和初始种子位。每局保持现有 60/90/120 秒规则，赛事运行时按固定步长快速模拟。

## 数据与页面

`tournament.js` 管理赛制、对阵、结果、排名和阶段推进，不访问 DOM；`match.js` 支持双人左右出生，并允许按参赛者 ID 固定随机流。`tournament-ui.js` 管理侧边抽屉的新建表单、赛事列表、总览、赛程、排名和报告。赛事保存到浏览器本地存储，刷新后能继续下一轮。创建时从 12 种策略中选择八种不同 Agent，输入赛事名称与种子；赛程报告展示每轮对阵、两局 VP、晋级路径和最终排名。

本版按用户未明确选择的赛程单位采用传统一对一；四方混战赛程、实时逐场观战、录像和跨设备同步留给后续版本。已有单局功能和 GitHub Pages 静态部署保持可用。
