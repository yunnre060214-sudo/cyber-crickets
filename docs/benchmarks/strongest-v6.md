# 「最强」v6 升级与发布评测

日期：2026-09-28。基线：v5 提交 `5c4aad40bbe7edf0932e51d342a538bcf9cde9ca`。本轮首选 v6：在新种子评测中把胜局从 51/72 提升到 68/72，并改善原 400 秒败局；它仍有明确败局，不是必胜策略。

## 实现变化

- 长局前期投资能继续扩张的无主前沿，接战后优先补洞、回收紧凑边界。
- 按当前资源总量换算边际 VP，估计资源保有时间，保护受到邻接敌军威胁的己方资源。
- 使用每个对手公开的 VP/s 与当前比分检查静态终局差，识别自己领先时的反超风险。
- 首步采用规则固有概率；虚拟占领同步更新双方支援、敌压与资源路径；按目标格去重后再执行 Beam 前瞻。
- 更新单局和赛事 Worker 的模块版本标记，避免浏览器继续加载旧算法。

`rules.js` 与基线逐字一致。地图、VP 公式、决策频率、同步结算、出生位及随机机制不变；新增对手统计对所有 Agent 相同。

## 证据边界

固定种子、不同时间长度及出生轮换存在相关性；72 局只有 3 张新地图，单挑组只有 1 张地图。因此这里的比例只描述这组评测，不能解释为全地图胜率。未覆盖所有阵容或超过 400 秒的策略强度；表中明确包含退步局。

资源保有时间、护点收益、边界奖励和静态终局投影是启发式。首步规则成功率也不包含同轮争抢造成的最终失占概率。

原始 JSON 保留本机决策墙钟耗时；新种子组每局平均决策耗时的均值为 0.099 → 0.089 ms。这受机器、运行次序、地图轨迹及后台负载影响，不代表统一 CPU 预算或跨设备性能结论。

已知继承问题：引擎最近资源扫描在找到距离 1 时即可提前结束；某些资源格因枚举顺序会报告距离 1、吸引值 6，而应为距离 0、吸引值 12。本轮保留现有行为，基线和 v6 均受影响；后续修复需要重新评测。
